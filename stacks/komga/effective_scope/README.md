# Effective persistent scope observer

This host tool derives Komga 1.28.1's five persistent paths through the exact packaged Spring Boot ConfigData implementation and typed `KomgaProperties` binder. It never starts a Spring application context, scanner, datasource or reader daemon. It replaces an unrecoverable temporary observer with maintained source; historical reports remain historical.

`parent.py` and `run_target.py` are disabled by default. Compiling source grants no configured observation, backup, publication or mutation authority. Their operational constants must be bound to independently reviewed actual inputs by an authorized operator; no live configuration belongs in this directory.

## Build and source checks

Use JDK 21 to compile Java 17-compatible output:

```sh
python3 -I -B run_source_tests.py --java-home /path/to/jdk-21
python3 -I -B build.py --java-home /path/to/jdk-21 --output /private/new-observer-packet
```

The build requires a new private directory, runs unprivileged, copies only the checked source manifest and verifies the complete generated class inventory and exact hashes. It never runs Docker. The artifacts map supplies independently reviewable producer and parent byte references. It is not an acceptance receipt.

All five target classes are required, including `KomgaEffectiveScope$Held.class` and `TargetEffectiveScopeCase$Observation.class`. The operational parent needs the collector, its Held class and the public metadata helper. The source gate proves a newly isolated classpath fails when either nested target artifact is missing. It does not rely on ambient compiled files.

The required repository-validation job runs source/compile checks with its installed JDK 21. It does not pull Komga or observe any configured state. The separate disabled target runner exercises actual packaged ConfigData/binding with disposable configuration only. The host helper is not installed in a custom image and its CI step publishes no image. Actual-image results and a configured observation must be recorded separately.

## Actual source and supported configuration

The daemon image is an unbound runtime input (`IMAGE=None`); the application JAR, source commit and all 157 ordered manifest dependency hashes are explicit. `original-public-dependency-facts.json` contains public JAR/provider-resource facts only; host inode/device metadata is deliberately omitted. Changes require a fresh actual public-image source join, not a version-string assumption.

The bridge supplies original explicit system properties, environment and application arguments to the packaged Spring environment. It calls the actual finite EPP/ConfigData/binder implementations. It preserves the actual equal-order VCAP-before-JSON order and never passes null to an API that needs a SpringApplication instance. Known no-op providers are skipped only after their activating class/resource is proved absent.

The observer supports normal packaged application resources and direct `/config/application[-profile].yml`, `.yaml` or `.properties` files. It uses the packaged loaders to inspect decoded documents, including inactive profiles, before loading the same captured bytes. Uncaptured JVM-default placeholders, dynamic placeholder keys, unsupported imports/property origins and unclosed resources refuse. It never invents missing JVM defaults. File/profile/placeholder resolution uses the real framework. Normal file resources resolve through `Resource.getFile()` before the same path and metadata checks. Absent XML candidates are recorded, while an existing XML configuration refuses.

The original parent preserves the complete inspected service and original process epoch/cmdline/environment, plus all 158 public code JARs and original configuration/scope nodes through the final exchange. Original root, ancestor and initially scanned direct nodes retain no-follow path descriptors until the parent exits. This prevents unlink/recreate from reusing an unheld inode before a scope is selected. The descriptors track identity, not database contents or payload timestamps. The existing media/state mounts stay in the original service closure; only config is mounted read-only into the disposable observer. Extra overlays over application/config paths refuse.

The disposable child has no network or healthcheck, a read-only root, UID 1000, dropped capabilities, no-new-privileges and finite resources. Supplier/source ownership and original descriptors are checked. The pending report bytes are never rewritten. Final ACK requires original process/config/source/pipe closure, and only the exact exited observation child can be removed. Bind checks require a list with the exact duplicate-preserving source/destination/options census. Docker list order carries no authority.

## Existing reader contract

The output retains exactly seven references: producer, parent_source, report, ack, runtime, acceptance and parent_ack. The existing reader SourceCohort accepts these byte-hash source references, including the compiled binary producer; no additional grant or source role is introduced. Supply the newly reviewed producer and parent pins in a fresh original-bound SourceCohort. Never substitute old temporary paths or re-sign old reports.

Every backup/publication/mutation flag remains false. The result covers five persistent paths, not library settings, NFS behavior, reader pause/resume, publication eligibility or data preservation. Connected-factory and configured acceptance retain their existing independent gates.

## Verified boundary

All ten disposable cases passed against the reviewed public Komga 1.28.1 JAR and its exact 157 dependencies: defaults, precedence, profiles, a normal file import, configtree refusal, changed configuration refusal, missing JVM-default refusal, an explicit JVM default, an inactive document refusal and heap-only environment handling. These use the same collector classes, real ConfigData implementation and typed binder. Each test container exits and passes its exact profile before cleanup.

The earlier source gate ran 85 host/JDK controls plus two compiled-binary reader projection controls. This branch adds six Python parent controls, bringing that owning Python suite to 38; its complete host/JDK gate remains a separate check. The two projection controls use the existing source fixture and do not prove configured Parent admission. Fresh original-process collection, same-pipe acknowledgement, SourceCohort installation and connected NFS/reader execution remain unverified. No task requiring those operations is complete.

Before a configured observation, bind the reviewed actual image, original container and new private output in a separate operator copy. Bind the six `supplier_pins` from the build artifacts: `owned.py`, collector source, collector class, its Held class, public metadata class and public dependency facts. The parent checks its own source separately. Preserve the exact supplier ownership/mode checks. Never put the binding or runtime output in this public directory. An image ID alone does not establish provenance. Join all original process JAR bytes to the public source facts and keep image platform/descriptor identities separate.

## Explicit disposable reader originals

The default service route retains its production mount destinations unchanged.
For the maintained plan13 fixture, `PLAN` may additionally contain
`bootstrap_originals: {plan, source}`. Both values are original
`{path, sha256, signature9}` references. The source must match the pinned
`genuine_application_bootstrap.py`; the plan remains a UID1000 private regular
file. The observer retains their original descriptors, full9 and ancestor5
through final closure. It does not execute bootstrap code.

This branch requires the original nonce, purpose-labelled reader, image, complete
static profile and runtime epoch. It derives exactly two bind mounts from the
original declaration: private reader state at `/config` writable, and the
original `G/L` library at its same absolute destination read-only. The declared
`G/R` retention remains outside the library. Extra, duplicate, writable-library,
foreign and application overlays refuse, even if repeated in a supplied profile.
No caller mount list or generic destination-prefix exception is accepted.

Only configuration is mounted into the observer child, read-only, as before.
Historical bootstrap directory vectors are not refreshed or presented as fresh
physical/NFS facts. Actual code JARs, process, configuration, report/ACK and all
seven output-reference checks remain unchanged. This compatibility branch grants
no connected factory, NFS, publication, mutation or reader-resume acceptance.

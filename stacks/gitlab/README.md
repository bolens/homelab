# GitLab

GitLab is a self-hosted DevSecOps platform providing Git repositories, CI/CD pipelines, issue tracking, and a container registry.

**Website:** https://about.gitlab.com
**Docs:** https://docs.gitlab.com/ee/install/docker.html
**GitHub:** https://github.com/gitlabhq/gitlabhq

## Usage

Accessed via browser through a Caddy reverse proxy. Hosts source code, runs pipelines via connected gitlab-runners, and optionally serves a built-in container registry. First-time setup requires retrieving the initial root password from the container.

## Setup

1. Copy `stack.env.example` to `stack.env` and fill in required values.
2. Set TZ to your local timezone.
3. Retrieve the initial root password: `docker exec -it gitlab grep 'Password:' /etc/gitlab/initial_root_password`
4. Deploy: `docker compose up -d`

## Environment variables

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| TZ | No | America/New_York | Container timezone |

## Notes

- GitLab is memory-hungry; allocate at least 4 GB RAM to the host.
- Caddy snippet is generated by prepare-stack.sh; set your hostname before deploying.
- Pair with the gitlab-runners stack to enable CI/CD pipeline execution.
- The initial_root_password file is deleted after 24 hours; save the password immediately.

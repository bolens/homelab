# Archive-one lifecycle composition

This proposal adds a finite archive branch to the same `LifecycleParent` source,
not a second lifecycle owner. Negative-five version9 behavior is retained.
Archive version10 uses kind `reviewed-archive-one-lifecycle-protocol`, action
`archive-one`, and the same continuously bound container, source, event, IPC,
private operation and actual child profile algorithms. Neither provider parent
pin is enabled. No service was read, stopped, changed, restarted or queried by
this proposal or its tests.

## Exact inputs and code roles

Archive plan retains the existing fields except `action_inputs` and
`admission_source_sha256`; it adds `action` and an exact regular `backup_provider`
ref. `provider` is the checked archive action; `producer` is the archive evidence
adapter; `observer` is the finite terminal-vector partition. `producer_inputs`
contains exactly `archive_request` and `archive_scopes`. The request has only
version1, native primary-key owner and operation_id. Source paths come from the
canonical installed Controller/catalog; no caller archive path, timestamp,
eleven-book selection or five-specific admission is accepted.

All host code/proof refs supplied to the parent remain original private regular
0600 refs with full9/SHA. Neutral backup helpers likewise require original
private code copies, not relaxed Git/public permissions. Runtime installation
must stage the explicit checked code closure in a private directory; copying
ignored configuration into a code closure is forbidden. Source byte hashes must
match `source-manifest.json` and all internal action/proof/probe/helper pins.

Native DATA/library geometry is derived by the checked fresh native probe and
actual configured scope. Writer-mutating mount sources are limited to exact
native DATA/library, scratch, retention and private operation roots. Extra
writable ancestors or arbitrary writable sources hold. Image-code overlays at
`/app` or beneath it hold. Backup additionally requires reader bind Sources
mounted at their original canonical HOST spelling. It copies the entire config,
independently restores it and verifies all schema/table fingerprints and raw
source/copy/restore facts; this produces no stopped-reader or mutation grant.
The private backup child has `TMPDIR` equal to its operation/backup directory.
The minimal backup-helper successor returns its completed original file/node
vectors after a final raw closure. The child and neutral producer carry those
originals through return callbacks and conditional HOST/CHILD comparisons; they
never replace them with newly measured copy facts.

Backup controls are exactly eight roles: stopped_runtime, backup_ack,
backup_manifest, backup_acceptance, schema, reader_snapshot, archive_request,
custody. `phase-custody` emits original regular proof refs and schema1 birth seed
only after the actual per-phase input is durable and hashed. Additional immutable
proof `archive_sdk_map` is the original plan SDK ref, outside the eight roles.
It is read against original full9/SHA before callbacks; input.sdk_map must equal
its source-controlled CHILD translation. No map is regenerated or resigned.
Canonical SDK→birth→same lifecycle pipe→configured scope remains the provider's
actual path; successful actual child birth is required before repair ACK.

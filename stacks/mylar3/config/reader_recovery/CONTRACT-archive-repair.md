# Archive-one provider source proposal

This proposal implements a distinct source-pinned one-repair child and pure input builder. It changes no installed source or application state. `PARENT_SOURCE_SHA` remains `None`; actual CLI execution stops before SDK loading. T011–T013 remain open. No JSON, HTTP result, queue record or caller Boolean can construct the native preparation, reader lease or adoption object.

## Implemented construction and consumption

`comic_archive_repair_protocol.phase_input` accepts one exact native primary-key owner and operation ID. It builds an `archive-one` input, an exact `/lsiopy/bin/python3 -I -B` command template with one input-hash placeholder, and the resulting command. This builder supplies no custody or grant. There is no caller archive path, URL, witness, native snapshot or alternate operation ID.

`comic_archive_repair_action` checks source/input/complete SDK-map bytes and original kernel facts. The SDK loader imports only canonical installed classes after checking every mapped source, preserves original map/source ancestors, and includes the new existing-preparation module before any operation. The birth helper receives the actual unchanged `sys.orig_argv`; lifecycle receives the same birth token/channel; `NativeConfiguredScope` derives the actual configured Controller and existing Writer.

`execute_one` uses that exact pair and one Writer lifetime. A new operation creates a genuine preparation, stopped-reader lease, adoption and preimage, then performs install/complete. An existing operation uses `publication_archive_preparation_existing.from_existing`; missing original preparation/stage provenance cannot replay PREPARE or generate a new ID. This route never calls ordinary import, five-book SQL/admission, generic lineage or worker Store.

The provider writes exclusive `execution-originals.json` before exchange, containing the adoption baseline file's original signature/hash, original preparation file/signature/hash, completed preparation directory signature and full reader binding. These records describe owning observations; they do not reconstruct objects. Uncertain exchange/COMMIT/clear or lost ACK retains custody and raises. No automatic retry or cleanup exists. `rollback_owned` accepts only the live exact adoption object in a proven installed/reversed phase, performs its typed reverse/rollback terminal clear, then carries the resulting vectors; an uncertain object refuses.

`verify_one` consumes the parent-bound original execution record and baseline identity, derives the actual finite forward or rollback journal from native source, and calls the separate independent verifier. It copies complete file, ancestor, absence, catalog-claim and namespace tuples before later lifecycle/watch/report callbacks. Final raw closure follows all helpers before ACK. It returns factual repair/reference observations; ordinary import, publication, reader indexing, automatic replay and resume rights remain false.

## Dedicated producer and parent requirements

The existing negative-five backup producer is unsuitable: `comic_reader_proof_producer.backup_controls` compiles five BOOK transitions, eleven-row selection and reviewed timestamp semantics. These cannot be relabeled as an archive proof.

The source-bound archive producer must implement this exact finite replacement:

1. Include all affected native/workflow/config state and exact original source custody required by the owning live workflow. Capture complete coherent main/tasks database schemas and typed all-table multiset through the detached observation primitive in `publication_archive_reader.observe`; capture active and deleted BOOK records and actual MEDIA/page references, without guessing URI spelling. Never open SQLite writable on a source.
2. Emit exactly eight checked archive control references: `stopped_runtime`, `backup_ack`, `backup_manifest`, `backup_acceptance`, `schema`, `reader_snapshot`, `archive_request`, `custody`. `archive_request` is exactly version 1 + owner + operation ID. `reader_snapshot` binds every main/tasks schema/table, original current and independent restore pairs. `custody` joins fresh physical current/restore pairs to the exact accepted copy/restore output references. No timestamp/five-row plan is present. Each reference must preserve its actual output SHA and original signature9; new outputs cannot use historical helper/output labels.
3. After the actual per-phase input is fsynced/hashed, emit the generic lifecycle sidecar using actual command/input/source/nonce and a continuous inherited parent channel. It includes all eight CHILD control refs plus `native_scope` and `archive_scopes`; the latter contains exact private scratch/retention roots outside all scanned roots, DATA, config and restore. Capture kernel facts in the actual child birth namespace; mismatches hold, never restamp. Lifecycle's `reader` field remains its actual two-database coherent `current_pairs`/`restore_pairs` and backup references. Its installed format accepts an arbitrary source-bound proof *role map*, but this action consumer restricts its required roles to the eight above; this is not a generic authority bypass.
4. For an existing US2 preparation, carry its original owning preparation ACK's full preparation.json signature/hash and original completed stage directory9 into lifecycle vectors. `from_existing` must find both original facts. Fresh status/re-read cannot replace missing historical directory provenance.
5. On actual execute ACK, preserve the provider output reference and original `execution-originals.json`, adoption baseline file9/hash and completed stage directory9. The independent verify phase uses a separate private operation and the original execute reference. Parent custody must carry baseline original9 before the verifier constructor; it cannot freshly adopt it after process exit. Stop remains continuous throughout both children.
6. The parent must source-bind this action/provider/SDK graph as a distinct finite action, validate actual native held process and worker/static mounts, and challenge the actual child pipe. Its verified ACK plus fresh independent observer vectors must close before any restart. Neither the current five-member parent input nor its five-specific phase producer implements these archive branches. No `PARENT_SOURCE_SHA` may be set before this concrete archive producer/parent composition is reviewed and exercised.

These are missing owning producer/parent functions, not an unspecified new runtime service. No permanent reader database mount or new socket/network access is proposed. A selected child needs only scoped existing native DATA/library paths, stopped reader config and restore, checked code/control RO, existing Writer lock/native catalogue RW for the actual dedicated exchange/ComicSize transition, and operation/scratch/retention RW. Exact temporary mounts and backup scope remain subject to the parent's finite profile contract; this proposal grants no Docker execution.

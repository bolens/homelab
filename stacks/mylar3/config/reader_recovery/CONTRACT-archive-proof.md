# Archive-only neutral proof producer proposal

This source-only producer composes the existing full-config backup, independent restore, complete SQLite schema/table observation and physical pair algorithms. It emits factual eight-role evidence; it does not stop services, mint stopped custody, authorize adoption or enable the provider's absent parent pin.

The source-pinned host parent calls `produce(phase, request, watch=parent.continuous)`. Request keys are exactly `version`, `phase`, `nonce`, `operation`, `deadline_monotonic`, `parent_plan`, `parent_source`, `context`. The parent's source-bound plan selects `action=archive-one` and `producer_inputs={archive_request,archive_scopes}`. The archive request contains only version, owner primary key and operation ID. Original host scopes contain version, scratch and retention_root. The parent provides its actual finite mapping and `same_runtime` projection; a Boolean callback is rejected.

`backup-controls` context is exactly `{backup,observations}`. Backup contains the fresh neutral helper manifest, independent restore root and actual helper acknowledgement. The producer source-joins and independently checks every config/source/backup/restore member, attributes, namespace and complete database proof. It creates exclusive fsynced private outputs under `operation/archive-proofs`. Its result is `{controls,archive_scopes}` with HOST references. Controls are exactly `stopped_runtime`, `backup_ack`, `backup_manifest`, `backup_acceptance`, `schema`, `reader_snapshot`, `archive_request`, `custody`. The generated archive-scopes file contains CHILD paths derived by original mount roundtrip before the provider input is hashed. It does not inherit negative-five plans, eleven BOOK rows, timestamp encoding or SQL mutation semantics.

`phase-custody` context is exactly `{backup,controls,archive_scopes,observations,phase,invocation,stage}`. Stage is prebirth, and phase is execute or verify-terminal. Verify adds `execution_originals` only. Invocation contains actual input path/hash, full command, nonce, parent source hash and provider source hash. The exact twelve-element command is Python -I -B, provider, --phase, --input, --input-sha256, --source-sha256; the input command template replaces only the input hash value with `<INPUT_SHA256>`. No input-hash fixed point or wrapper argv is accepted.

Result is `{reader,proofs,birth_seed}`. Reader paths and proof values inside the reader are CHILD geometry; proof references outside it remain HOST references for the parent to translate once. Birth seed uses existing selected-child-native-scope-birth schema1 and actual invocation/config geometry, with no invented CHILD ancestor identities. Native DATA/config.ini and library are checked against original mounts and config bytes. The worker library destination is derived independently from the same physical native library, allowing distinct container destinations and rejecting shadowed or ambiguous projections. Complete original current and restore pair tuples remain unchanged; actual selected-child kernel comparison may refuse cross-namespace signatures rather than refreshing them.

Verify joins the source-bound original execution record to fixed adoption baseline and preparation paths derived from owner/op/native DATA/retention.

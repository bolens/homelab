# Genuine archive scenario checkpoint

Plan13 implements a prospective private-common-root NFS publication protocol.
This source batch does not complete feature 023 T026/T029 or feature 024

## Source protocol

The actual chain remains `LifecycleParent.execute_archive()` → selected action
→ installed `Birth.from_checked_parent()` → lifecycle `from_birth()` →
`NativeConfiguredScope.from_checked_parent()` → owning preparation/reader/adoption.
Default Parent/provider admission remains disabled. The configured installer
must install the coherent new source closure before any runtime attempt.

Plan13 adds `publication_geometry` with version1 kind
`private-common-root-nfs` and original `{path, signature9}` references for G,
its direct library child L, and its direct private retention child R. G/L/R
must be distinct UID/GID1000 directories with mode0700 in legacy geometry v1.
Explicit geometry v2 `searchable-common-root-nfs` instead requires G mode0711
and L/R mode0700; it retains every descriptor, namespace and mount exclusion below. G's original full9,
all three directory descriptors and exact `{L,R}` namespace remain held.
Only descendant changes inside L/R are expected; G timestamp drift refuses.
The selected action gets one writable bind G→G, replacing separate L/R binds.
No nested bind, alias, overmount, other role overlap or extra G child is allowed.
The canary uses R as its neutral grandparent and removes its own canary before
retention admission. G is never a neutral canary grandparent.

Before Writer acquisition, the action requests `archive_publication` over its
original checked pipe. Parent joins the exact already-produced NFS-ready ref to
its consumed process-local NFS owner and original execute input. Custody seals
these facts separately from normal native observations. The one-use strategy
selection binds actual owner, operation, configured source/library/retention,
NFS mount/export/device and selected-child mountinfo. Source and stage must
share the same actual mount ID. Device equality alone does not qualify.
Selection precedes pending-marker creation; no failed exchange triggers fallback.

The configured Controller/Writer factory allocates fresh objects. A fixture
transition already inside the owning Writer session validates its supplied pair
against the exact original process-local session record and existing Writer
proof, retaining record identity across callbacks; it never invokes that factory
again. The separate terminal verifier selects its final pair after preparation
binding, whose own factory call replaces the Scope's current pair.

Action input v3 contains exact `publication_protocol=rename-link-v1` and
`terminal=forward|rollback`. Private request v2 explicitly selects terminal
behavior; old request v1 selects forward in plan13. Old plans10–12 and input
versions1–2 retain their exact schemas and local exchange behavior. The private
request is not an added public API route or an uncertain-operation replay.

For the original disposable fixture only, private request v3 adds an exact
`fixture_transition` joining original Bootstrap/catalog records and the actual
catalog-derived genesis archive. Input v4 carries the two factual copies through
the existing checked Tree; Root retains the original UID1000 references. No
caller supplies replacement archive bytes. Request v1/v2 and input v1/v2/v3
retain their existing schemas and behavior.

After genuine stopped-reader custody and existing Writer admission, the action
durably preserves the valid genesis, derives one supported missing directory
slash and verifies byte-exact repair back to genesis before changing the held
fixture inode. Originals v2 and terminal consumers retain this causal record
and every stage vector. Forward repair reproduces genesis; explicit rollback
restores the malformed successor. Failure or uncertainty preserves the hold
without automatic reset or replay. These fixture records grant no live import,
ACK, publication acceptance or independent custody.

Library and DATA may have disjoint ancestry. Fixture JSON writes admit only their
original stage ancestors; retained successor seals continue to close both branches.
If complete typed catalog snapshots are identical, forward/reverse skip the SQL
UPDATE and retain original database bytes/full9 and every companion absence.
Actual catalog changes still require the live connection's owned journal.

The six source-owned steps are retain-displaced (no-clobber hardlink),
detach-source, publish (no-clobber hardlink), detach-stage, retain-original
(no-clobber hardlink), and detach-displaced. Each has a durable intent and done
receipt, separate for install and explicit reverse. Original source/candidate
FDs, streaming hashes, metadata and exact finite nlink transitions remain bound
through callbacks. Inline file/FD/ancestor/absence/namespace CAS follows the
last callbacks before each syscall. Baseline v2 and the independent verifier
cover the protocol, full phase journal, original G and displaced absences.
Legacy baseline v1 schemas remain unchanged.

An explicit rollback request installs then reverses the same original live
capability before typed rollback completion and actual terminal observation.
Unknown syscall/fsync/receipt/SQL/ACK outcomes retain pending markers and both
archive revisions. They grant no replay, automatic restoration or reader resume.

The exclusion prerequisite covers cooperating applications: the original Writer
is exclusive, the reader is stopped, the worker is inactive, and no independent
actor writes the selected names during the entire operation. UID1000/0700 alone
does not exclude another same-UID process or root. NFS has no conditional
unlink-by-inode primitive. An actor replacing a name after the final CAS and
inside unlink can evade detection; a local test demonstrates this unsupported
actor rather than asserting impossible preservation. Replacements observed at
callback boundaries refuse before the next destructive syscall.
